§14 Runbook

14. Runbook triển khai & vận hành

Tuân thủ quy trình trong docs/cutover-runbook.md. Dưới đây tóm tắt các mốc quan trọng quanh thời điểm go-live.

MốcCông việc
T-24hUAT 5 vai trò, ký biên bản, import ma trận A2
T-2hSnapshot DB, backup uploads, freeze cấu hình
T0docker compose up -d; entrypoint chạy prisma migrate deploy
T+5pdocker exec asms_backend npm run bootstrap:auth (lần đầu)
T+10pĐổi mật khẩu admin, tạo user thật qua UI Cài đặt
T+20ppost-deploy-smoke: uat-role + uc-smoke + dashboard-audit
Hypercare2–4 tuần: theo dõi /api/v1/health, log 5xx, backup, disk

14.1 Lệnh vận hành thường dùng

Verify sau khi up
curl -k https://asms.vtx.local/api/v1/health # mong đợi: {"success":true,"data":{"status":"ok","database":"reachable"}}
Xem log backend
docker compose logs -f backend
Backup thủ công
bash /opt/asms/scripts/backup-production.sh
Import RBAC
docker compose exec backend node scripts/import-role-permissions.mjs
Restart containers
docker compose restart backend
Xem container đang chạy
docker compose ps
Post-deploy smoke test
docker compose exec backend node scripts/post-deploy-smoke.mjs
Tip: chạy node scripts/post-deploy-smoke.mjs sau mỗi lần deploy để tự động kiểm tra health, đăng nhập, RBAC và audit log. Xem chi tiết docs/production-smoke.md.

§15 Chịu lỗi

15. Khả năng chịu lỗi & phục hồi

RPO
~24 giờ (backup cron 1 lần/ngày lúc 02:00)
RTO
Phụ thuộc kích thước DB
Rollback
Image tag cũ + DB snapshot

15.1 Quy trình restore khi sự cố

  1. Liệt kê các bản backup: ls -lh /opt/asms/backups/
  2. Chọn bản asms_db_YYYYMMDD.sql.gz + asms_uploads_YYYYMMDD.tar.gz mới nhất.
  3. Dừng containers: docker compose down
  4. Khôi phục DB: gunzip -c asms_db_*.sql.gz | docker exec -i asms-db psql -U asms
  5. Khôi phục uploads: tar -xzf asms_uploads_*.tar.gz -C backend/uploads
  6. Redeploy image trước đó: docker compose up -d
  7. Verify health: curl /api/v1/health và đăng nhập thử.
  8. Ghi incident + thông báo VTX theo quy trình.

15.2 Sự cố thường gặp

Sự cốTriệu chứngXử lý nhanh
Backend không khởi độngdocker ps thấy Restartingdocker logs asms-backend; kiểm tra DATABASE_URL, JWT_SECRET
DB không kết nốiHealth trả database: unreachableKiểm tra asms-db container, pg_isready, firewall port 5432
Nginx 502Trình duyệt trả 502 Bad GatewayBackend down hoặc listen sai cổng; kiểm tra docker logs
Disk đầyUpload thất bại, DB không ghiChạy backup-production.sh ngay, xóa backup cũ hơn retention
Mất quyền adminKhông đăng nhập được adminChạy lại bootstrap:auth hoặc reset qua DB trực tiếp
Lưu ý: nếu sự cố xảy ra trong vòng 24h sau backup gần nhất, dữ liệu phát sinh sau thời điểm đó sẽ mất. Có thể giảm RPO bằng cách tăng tần suất backup hoặc bật PostgreSQL streaming replication.

§16 Giám sát

16. Giám sát đề xuất

Hệ thống on-premise cần tối thiểu 4 trụ cột giám sát: uptime, log, disk, backup.

Uptime
Probe định kỳ
Mục tiêuGET /api/v1/health mỗi 1 phút
Cảnh báoHTTP khác 200 hoặc database: unreachable > 2 lần liên tiếp
Logs
Tổng hợp log tập trung
BackendMorgan combined to Docker JSON driver
Tổng hợpLoki/ELK hoặc journald to xoay log theo ngày
Disk
Dung lượng lưu trữ
Ngưỡng cảnh báo> 80% trên DB host và backup host
Upload volumeTăng theo tài liệu đính kèm
Backup verification
Đảm bảo backup khả dụng
Tần suấtDrill restore trên staging mỗi tuần
Lưu logMỗi lần chạy backup-production.sh phải có log
Curl healthcheck mẫu
curl -s https://asms.vtx.local/api/v1/health | jq . # Response mẫu: # { "success": true, "data": { "status": "ok", "database": "reachable", "uptime": 3600 } }
Khuyến nghị: với hệ thống quy mô vài chục user, có thể dùng Uptime Kuma (self-hosted, miễn phí) để probe /api/v1/health và gửi cảnh báo qua Telegram/email khi down. Logs tổng hợp bằng Dozzle hoặc docker logs + logrotate.

§17 FAQ

17. Câu hỏi thường gặp (FAQ)

Mở trình duyệt báo "Không truy cập được trang"
Kiểm tra: (1) Docker đang chạy? (2) Lệnh docker compose ps có 2 dòng running? (3) Máy bạn cùng mạng LAN với server? (4) Firewall có chặn cổng 80 không?
Đăng nhập được nhưng màn hình trắng hoặc lỗi liên tục
Thường do cấu hình sai. Chạy docker compose logs backend, chụp màn hình gửi Unicom. Không tự sửa file trong thư mục phần mềm.
Quên mật khẩu admin
Liên hệ Unicom hoặc IT có quyền server để reset qua lệnh bootstrap (cần truy cập máy chủ).
Cần tắt máy chủ bảo trì
Chạy docker compose down trước khi tắt. Sau khi bật server lại: docker compose up -d. Dữ liệu vẫn giữ nếu không xóa thư mục uploads và DB.
Cập nhật phiên bản mới
Unicom gửi file .tar phiên bản mới + hướng dẫn. Luôn backup database trước khi cập nhật. Chi tiết kỹ thuật: xem docs/cutover-runbook.md.
On-premise là gì? Tại sao không dùng cloud?
On-premise = phần mềm chạy trên server nội bộ của VTX, không qua cloud. Chọn on-premise vì: (1) dữ liệu không ra ngoài, (2) tận dụng hạ tầng sẵn có, (3) không phụ thuộc nhà cung cấp cloud, (4) đáp ứng yêu cầu an toàn thông tin nội bộ.
Cổng nào cần mở trên firewall?
Chỉ cần mở 80 và 443 (HTTP/HTTPS) từ Internet vào Nginx. Các cổng 4001 (backend), 5432 (DB) chỉ trong mạng nội bộ, không public.
Backup tự động chạy lúc nào?
Cron chạy scripts/backup-production.sh vào 02:00 hàng ngày. Output: asms_db_YYYYMMDD.sql.gz và asms_uploads_YYYYMMDD.tar.gz lưu ở /opt/asms/backups/, retention 30 ngày.

§20 Checklist

20. Checklist hoàn tất triển khai

Dùng danh sách này để xác nhận mỗi bước đã hoàn tất trước khi ký biên bản nghiệm thu.

Giai đoạn chuẩn bị
  • Server đạt thông số tối thiểu (CPU, RAM, disk)
  • Đã cài Docker Desktop / Docker Engine
  • Đã nhận file bàn giao từ Unicom
  • Đã cấu hình PostgreSQL (tạo DB asms)
  • Đã điền file .env với JWT_SECRET >= 32 ký tự
  • Đã tạo thư mục backend/uploads/documents và backend/uploads/workflow
Giai đoạn triển khai
  • docker compose up -d — 2 container running
  • docker compose exec backend npx prisma migrate deploy — thành công
  • docker compose exec backend npm run bootstrap:auth — tài khoản admin tạo
  • curl /api/v1/health — trả {"success":true,"data":{"status":"ok","database":"reachable"}}
  • Đăng nhập web bằng tài khoản admin → Dashboard hiển thị
  • Menu bên trái hiển thị đủ các mục (Hợp đồng, Khách hàng, Bảo hành...)
  • Import ma trận RBAC qua scripts/import-role-permissions.mjs
  • Tạo thử 1 user thật cho mỗi vai trò
Giai đoạn vận hành
  • Đổi mật khẩu admin ngay sau lần đầu đăng nhập
  • Cấu hình backup cron (02:00 hàng ngày) — chạy thử 1 lần
  • Kiểm tra backup gần nhất: ls -lh /opt/asms/backups/
  • Đã cài đặt cảnh báo Uptime Kuma / monitoring
  • Firewall chỉ mở 80/443 ra ngoài, 5432 không public
  • Nginx cấu hình TLS (cert từ Let's Encrypt hoặc CA nội bộ)
  • Ký biên bản nghiệm thu cài đặt với Unicom
  • Bàn giao tài liệu + account admin cho VTX
