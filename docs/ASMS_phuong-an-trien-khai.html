1. Giới thiệu & phạm vi

Tài liệu này mô tả toàn bộ quy trình triển khai ASMS từ máy dev đến server production nội bộ VTX, bám sát cấu hình thực tế trong repository asms.

1.1 ASMS là gì?

ASMS (After-Sales Management System) là ERP web quản lý vòng đời hậu mãi: Khách hàng → Hợp đồng → Bàn giao & Huấn luyện → Bảo hành/Sửa chữa → Phản ánh → Báo cáo điều hành.

1.2 Thành phần kỹ thuật

🖥

Frontend

React 18 · Vite · Tailwind · shadcn/ui — Build static, phục vụ bởi Nginx

⚙️

Backend

Node.js 20 · Express 5 · TypeScript — API prefix /api/v1

🗄

Database

PostgreSQL 14+ · Prisma 6 — ~55 migration trong backend/prisma/migrations/

🐳

Container

Docker + Compose v2 — 2 service: frontend + backend

1.3 Mô hình triển khai VTX

  • On-premise: Server trong mạng nội bộ / VPN, không phụ thuộc cloud.
  • Bàn giao source: VTX nhận repo + tài liệu, tự build/deploy (dev hỗ trợ onsite nếu cần).
  • Không Redis: ASMS hiện không dùng Redis; session JWT stateless + refresh token trong DB.
  • Cron in-process: Job nhắc lịch/SLA chạy trong process Node backend (không cần worker riêng).

1.4 Phạm vi go-live v1 (màn FE)

12 menu sidebar: Dashboard, Hợp đồng, Bàn giao & HL, Bảo hành/SC, Sản phẩm, Vật tư, Khách hàng, Phản ánh, Báo cáo, Tài liệu, Quy trình, Cài đặt. Các route /de-tai, /cong-viec, /dao-tao ẩn menu — không nghiệm thu v1.

5. Hạ tầng & Triển khai

Hệ thống chạy trên nền tảng Docker, giúp môi trường DEV và PROD đồng nhất. ASMS không dùng Redis — session JWT stateless, cron chạy in-process trong backend.
  • Database: PostgreSQL 14+ (khuyến nghị 16).
  • Reverse Proxy: Nginx — SPA static + proxy /api/ → backend:4001.
  • Deployment: Build image asms-frontend + asms-backend, chạy qua docker-compose.yml trên server VTX.
  • Port API: Backend 4001, prefix /api/v1.

5.1 Frontend Dockerfile (root)

  • Stage 1: node:20-alpine — npm run build (không truyền VITE_API_URL → API relative).
  • Stage 2: nginx:1.27-alpine — copy dist/ + nginx.local.conf.

5.2 Backend Dockerfile

  • npm ci → prisma generate → npm run build (tsc).
  • Entrypoint: node dist/main.js (không tự migrate — chạy thủ công).
  • Khi khởi động: kết nối DB (retry 5 lần), seed definitions/settings, start cron notify.

5.3 docker-compose.yml

services:
  frontend:
    image: ${FRONTEND_IMAGE}
    container_name: asms_frontend
    restart: unless-stopped
    ports:
      - "${FRONTEND_PORT}:80"
    depends_on:
      backend:
        condition: service_started

  backend:
    image: ${BACKEND_IMAGE}
    container_name: asms_backend
    restart: unless-stopped
    env_file:
      - ./.env
    environment:
      PORT: "${BACKEND_PORT}"
      DATABASE_URL: "${DATABASE_URL}"
    ports:
      - "${BACKEND_PORT}:${BACKEND_PORT}"
    volumes:
      - ./backend/uploads:/app/uploads

5.4 Lệnh build image

Build từ thư mục gốc repo:
docker build -t asms-frontend:1.0.0 .
docker build -t asms-backend:1.0.0 ./backend

5.5 nginx.local.conf — proxy API

location /api/ {
    proxy_pass http://backend:4001/api/;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}

Tên host backend = tên service trong Compose (Docker DNS nội bộ).

8. Nginx reverse proxy & HTTPS (host)

Khuyến nghị đặt Nginx trên host (ngoài Docker) để terminate SSL, proxy vào container frontend.

8.1 Ví dụ cấu hình Nginx host

server {
    listen 443 ssl http2;
    server_name asms.vtx.local;

    ssl_certificate     /etc/ssl/certs/asms.crt;
    ssl_certificate_key /etc/ssl/private/asms.key;

    client_max_body_size 50M;   # upload tài liệu

    location / {
        proxy_pass http://127.0.0.1:80;   # FRONTEND_PORT
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
    }
}

server {
    listen 80;
    server_name asms.vtx.local;
    return 301 https://$host$request_uri;
}

8.2 Lưu ý upload file lớn

Đồng bộ client_max_body_size trên cả Nginx host và container FE nếu cần file > 1MB.

11. Triển khai Production (Remote Server)

Đóng gói image Docker và triển khai trên server nội bộ VTX (build trên server hoặc chuyển file .tar).

Cách 1: Build trên Server (có Git)
Clone tag release → tạo .env → docker build → docker compose up -d → migrate + bootstrap.
Cách 2: Triển khai Thủ công (chuyển image .tar)
docker build -t asms-frontend:1.0.0 .

docker save -o asms-frontend-1.0.0.tar asms-frontend:1.0.0
docker save -o asms-backend-1.0.0.tar asms-backend:1.0.0
scp *.tar docker-compose.yml .env user@IP:/opt/asms/
ssh user@IP "docker load -i asms-frontend-1.0.0.tar && docker load -i asms-backend-1.0.0.tar && docker compose up -d"

12. Database: migrate, bootstrap, seed

12.1 Prisma migrate — Production

KHÔNG dùng prisma migrate dev trên production. Chỉ dùng migrate deploy.
# Trong container hoặc máy có DATABASE_URL production
cd backend
npx prisma migrate deploy
npx prisma generate

Áp dụng tuần tự ~55 migration từ 20260429084424_init đến mới nhất.

12.2 Khởi động server tự động (mỗi lần start)

Backend startServer() luôn chạy (không phụ thuộc production):

  • seedDataDefinitions() — danh mục thuộc tính mặc định
  • ensureDefaultSystemSettings() — SLA, nhắc lịch…
  • ensureRolePermissionsSeeded() — ma trận quyền mặc định
  • ensureNotificationPreferencesForAllUsers()
  • startNotificationCron() — job SLA & nhắc ngày

Chỉ non-production: seedAuthUsers() tự chạy khi start (user demo).

12.3 Bootstrap production (một lần)

docker compose exec backend npm run bootstrap:auth

Script bootstrap-auth.ts tạo/idempotent:

  • 5 role hệ thống
  • 5 user demo (email *@demo.local, pass Password123!)
  • Definitions, điều khoản mẫu, workflow seed

Sau bootstrap: đổi mật khẩu admin; tạo user thật qua Cài đặt → Người dùng hoặc POST /api/v1/users (admin JWT).

19. Xử lý sự cố (troubleshooting)

API trả HTML thay JSON
Nguyên nhân: VITE_API_URL sai hoặc proxy /api chưa cấu hình.
Xử lý: Docker prod để trống VITE_API_URL; kiểm tra nginx.local.conf proxy backend:4001.
502 Bad Gateway khi gọi /api
Backend chưa chạy hoặc sai tên service Docker.
Xử lý: docker compose logs backend; đảm bảo service tên backend.
PostgreSQL connection failed
Sai DATABASE_URL, firewall chặn 5432, hoặc DB chưa sẵn sàng.
Xử lý: Backend retry 5 lần khi start; kiểm tra từ container: docker compose exec backend npm run db:check.
401 loop sau login
JWT hết hạn / refresh lỗi / clock skew server.
Xử lý: Xóa localStorage, login lại; đồng bộ NTP server.
403 khi tạo dữ liệu
Role không đủ quyền module.
Xử lý: Cài đặt → Phân quyền; kiểm tra role_permissions.
Upload file thất bại
Thiếu quyền ghi volume hoặc client_max_body_size nhỏ.
Xử lý: chmod thư mục uploads; tăng limit Nginx.
Migrate deploy lỗi
Schema lệch hoặc migration đã apply một phần.
Xử lý: Khôi phục backup; không sửa tay bảng _prisma_migrations trừ khi hiểu rõ.

docker compose logs -f --tail=100 backend
